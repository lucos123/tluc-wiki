# How Claude remembers your project

**URL**: https://code.claude.com/docs/en/memory.md  
**Source File**: [raw/articles/claude-code/context-memory-rules/memory.md](../../raw/articles/claude-code/context-memory-rules/memory.md)

## Executive Summary

This official Anthropic guide details the dual memory architecture of [Claude Code](../entities/Claude%20Code.md):
1. **CLAUDE.md files**: Human-authored instructions for persistent project guidelines, user preferences, and organization policies.
2. **Auto Memory**: Model-authored persistent notes automatically generated by Claude Code to record discovered patterns, corrections, and build quirks across turns.

The guide covers configuration hierarchies, file imports (`@path/to/import`), `.claude/rules/` path-scoping, symlinking `AGENTS.md`, and troubleshooting memory adherence.

---

## Dual Memory Architecture Comparison

| Feature | CLAUDE.md Files | Auto Memory |
| --- | --- | --- |
| **Author** | Human developer / Team | Claude Code (Model) |
| **Contents** | Coding standards, workflows, architecture | Discovered learnings, build fixes, user corrections |
| **Scope** | Managed policy, User (`~/.claude`), Project (`./CLAUDE.md`), Local (`./CLAUDE.local.md`) | Per repository (shared across Git worktrees) |
| **Context Loading** | Loaded at session start | First 200 lines / 25KB loaded at session start |
| **Best Used For** | Rules that cannot be inferred from code alone | Auto-accumulating project preferences without manual effort |

## Key Mechanisms

### 1. Load Resolution Order
CLAUDE.md files load strictly from broadest to most specific:
1. **Managed Policy**: `/etc/claude-code/CLAUDE.md` (IT/DevOps org-wide policies)
2. **User Instructions**: `~/.claude/CLAUDE.md` (Personal preferences across all projects)
3. **Project Instructions**: `./CLAUDE.md` or `./.claude/CLAUDE.md` (Shared team standards)
4. **Local Instructions**: `./CLAUDE.local.md` (Personal gitignored project notes)
5. **Subdirectory Instructions**: Loaded on-demand when Claude reads files in those subdirectories.

### 2. File Imports (`@path`)
- Syntax: `@README.md` or `@docs/git-instructions.md` expands and loads target files at launch.
- External imports resolving outside the working directory (e.g. `@~/.claude/my-project-instructions.md`) trigger an explicit user approval dialog on first launch.

### 3. Interoperability with `AGENTS.md`
- Claude Code reads `CLAUDE.md`, not `AGENTS.md`.
- To avoid duplication, `CLAUDE.md` can import `AGENTS.md` via `@AGENTS.md` or use a symlink (`ln -s AGENTS.md CLAUDE.md`).

### 4. Path-Scoped Rules (`.claude/rules/*.md`)
- Group topic-specific rules in `.claude/rules/` (e.g., `testing.md`, `security.md`).
- Scope rules to specific files using YAML frontmatter glob patterns:
```yaml
---
paths:
  - "src/api/**/*.ts"
---
```
Path-scoped rules trigger *only when matching files are read*, saving context space.
